# BOMBAR project control room

These artifacts are the durable interface between the project owner, the interactive Architect, fresh Builder sessions, and independent verification.

## Lifecycle

1. Work interactively with the Architect to complete `00`–`05` and the specifications.
2. Run `bash .bombar/validate-plan.sh` until the plan is mechanically valid.
3. Review the complete governed set as the project owner.
4. Commit it, then freeze approval with `bash .bombar/validate-plan.sh --freeze --approved-by "Name"`.
5. Commit `APPROVAL.json`.
6. Run `bash .bombar/run_bombar.sh` on a dedicated implementation branch.
7. Prepare independent verification with `bash .bombar/prepare-verification.sh`.
8. Perform any authorized live canary awake, then record final acceptance.

Changing any governed artifact after approval invalidates the digest and locks autonomous execution until it is reviewed and frozen again.

## Files

- `00_PRODUCT_BRIEF.md` — desired outcome, users, scope, and non-goals.
- `01_REPOSITORY_ASSESSMENT.md` — verified terrain and project state.
- `02_ARCHITECTURE.md` — target structure and boundaries.
- `03_INVARIANTS.md` — properties that must remain true.
- `04_ACCEPTANCE_CONTRACT.md` — frozen observable definition of success.
- `05_IMPLEMENTATION_PLAN.md` — dependency order and slice rationale.
- `specs/` — one bounded specification per fresh Builder session.
- `evidence/` — one execution record per completed slice.
- `APPROVAL.json` — content-addressed owner approval generated by BOMBAR.
- `BLOCKERS.md` — decisions or constraints that stop safe implementation.
